## Reuse and coverage

The twelve P3.1a directed scenarios are callable from
[`protocol_core_unit_tests.ml`](../test/core/protocol_core/protocol_core_unit_tests.ml),
and the existing generated runner accepts an optional elaborated circuit. The backend suite
uses those same scenarios, independent [`Program_access`](../f_model/program_access.ml)
predictions, scheduled inputs, store oracle, replay settings, and diagnostics against both
`Project.elaborate ~mode:Simulation` and `~mode:Implementation`. Each mode runs the 240
fresh-state scenarios at seed `20260920`, maximum size 32. Resource assertions separately
confirm `program`, 256x16, latency one, explicit `Flops`, and the behavioral versus selected-
implementation source roles.

The verification-only [`Program_memory_backend_design`](../test/integration/program_memory_backend/program_memory_backend_design.ml)
is the same context-registered consumer/RAM composition used by the Cyclesim suite. Its
emitter produces separate simulation and implementation Verilog. One HDL testbench drives
the full consumer interface and covers the acceptance gaps that the intentionally narrow
Tiny Tapeout diagnostic adapter cannot expose. It identifies the scenario, source role,
edge, observation, expected value, and actual value on failure.

The emitted-RTL cases are portable consumer-property checks rather than a translated copy of
the OCaml generator. Full directed and bounded generated coverage runs on both actual ASIC
backend circuits; emitted RTL independently covers every previously audited behavioral gap.
The depth-sized load remains covered on both backend circuits but is not repeated as a
256-word HDL transcript because it adds no emitted-role behavior beyond the checked address
and length boundaries.

## Undefined memory outputs

The abstract suite retains zero, all-ones, and address-derived poison. The real backends are
compared only for contract-defined reads. Disabled-output hold is checked within each
backend. HDL checks use case inequality for defined results and do not compare raw data when
response validity is low. Consequently implementation X values and arbitrary behavioral
post-write or unwritten values cannot become instructions or valid host responses, but are
not incorrectly required to agree across implementations. No poison, initialization, or
validity storage was added to synthesized logic.
