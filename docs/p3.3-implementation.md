# P3.3 core-to-engine integration implementation record

Date: 2026-09-20. The implementation and this record are uncommitted working-tree changes
on top of `61384c3` plus the preserved P3.2 correctness fixes. This is functional evidence
for the selected `m16`, one-lane configuration. It is not host transport, protocol-level
P4 acceptance, formal proof, mapped cost, or physical timing evidence.

## Implemented composition

[`Integrated_core`](../lib/integrated_core.ml) composes P3.1a program access, P3.2
execution, and [`Core_mechanisms`](../lib/core_mechanisms.ml). Program RAM remains an
external latency-one port. The adapter owns one shared input/event front end, one timing
block, separate eight-byte TX/RX FIFOs, one shift lane, and one central registered pin bank.
The independent model is not called by or imported into either RTL module.

| Instruction | Mechanism and completion |
| --- | --- |
| `Read_pins`, `Branch_pin` | Shared synchronized snapshot; accept and complete together, with the branch result in bit 0 |
| `Read_status`, `Ack_status` | Six sticky event bits; accept and complete together; acknowledgement is masked and a simultaneous set wins |
| `Write_pins_imm`, `Write_pins_reg` | Software side of the real bank; accepted masked push-pull/open-drain writes commit at that edge; invalid masks and engine ownership conflicts are refused without a partial write |
| `Wait_cycles_imm`, `Wait_cycles_reg` | Accepted once by `Timing`; complete at the accepted-delay deadline |
| `Wait_level`, `Wait_edge` | Shared snapshot/edge input; immediate level success, stale-edge rejection, optional timeout, either-edge adaptation, and event-over-timeout priority |
| `Start_periodic`, `Stop_periodic` | Immediate control of the independent periodic timer; ticks continue through core stalls and restart phase on each start |
| `Issue_transfer` | Complete descriptor validation and lane acceptance occur together; the instruction retires at acceptance and the lane continues in the background |
| `Fifo_push`, `Fifo_pop` | Real TX/RX byte FIFOs; immediate transfer when possible, retained delayed completion for blocking pressure, and refusal for pressured nonblocking operations |

The stable mechanism-reason byte is: `0` none, `1` unavailable, `2` invalid parameter,
`3` pin conflict, `4` FIFO full, `5` FIFO empty, `6` data out of range, `7` cancelled, and
`8` primitive failure. P3.2 separately records whether the failure was refusal or delayed
completion.

The descriptor is latched by `Shift_lane` at acceptance. Direction, bit order, idle values,
launch/sample phases, optional internal clock, initial delay, and internal pacing are
translated from the nine core fields; the adapter separately latches the shared observed
pacing pin and edge at the same acceptance. Later `Config` instructions cannot redirect an
active transfer. Output and clock pins are claimed at issue. Lane values and enables pass
through the bank's registered engine write; completion/fault clears output enable before
ownership release. ABORT dominates every pending bridge operation, so an old write cannot
reassert a released pin.

The current ISA descriptor contains a sixteen-bit TX value. Transfers through 32 bits are
supported when upper transmitted bits are zero, and RX can return all 32 bits. The FIFOs
remain explicit byte queues and are not silently packed into the descriptor. The ISA also
has no autonomous observed-start/cancel selector: issue starts the lane, observed pacing
uses the shared synchronized edge source, and host ABORT supplies prompt cancellation.

## Control contract

| Priority | Effect |
| --- | --- |
| Reset | Clear architectural/mechanism validity, release pins and queues, invalidate the program image |
| Disable | Cancel execution and mechanisms, release pins, clear queue occupancy, preserve a completed image |
| ABORT | Suppress same-edge issue/completion, halt without retirement, cancel waits/FIFO ownership/transfer cleanup, release all claims and output enables, and set `Aborted` when work was active |
| STOP | Latch a request and halt when P3.2 next raises `instruction_boundary_o`; already accepted engines continue |
| Single-step | Only while image-valid, paused at a nonterminal boundary, non-faulted, and engines idle; resume preserved state, execute one instruction including extension/stall, then halt at its boundary. A terminal normal `Halt` requires fresh RUN rather than re-executing the same slot |
| RUN | Fresh execution: clear architectural state and start at slot zero |

STOP during fetch, extension acquisition, mechanism offer, or mechanism wait waits for that
instruction's retirement or terminating fault. Completion/fault wins as the boundary and
no following fetch is accepted. A stopped core does not imply idle engines. Program access
continues to require both `halted_o` and the real `engines_idle_o`.

`engines_idle_o` requires no timing wait, accepted blocking FIFO operation, active/armed
lane, transfer bridge cleanup, engine claim, or pending engine bank request. FIFO occupancy,
software claims, and periodic timing do not count as an open transaction. A stepped
`Issue_transfer` therefore leaves the core halted and the engine busy; further step and
program-memory requests are rejected until cleanup finishes.

## Verification evidence

[`test/integration/core_engine/`](../test/integration/core_engine) contains seventeen inline
tests. Real assembled images are loaded, read back, verified, completed, and run through
P3.1a. Directed cases cover every delegated kind; pin snapshots/branches and both write
forms; exact immediate and delayed waits; event-over-timeout and ABORT-over-completion
collisions; status acknowledgement; periodic activity; FIFO full blocking and ordered
recovery; TX, RX, duplex, and latched observed pacing; software/external ownership refusal;
background transfer progress through a core wait and while halted; simultaneous control
priority; disable/reset cleanup; and halted-but-engine-active memory gating. The FIFO order
and ownership-conflict outcomes are derived from the independent `Fifo` and `Pin_bank`
models; primitive suites retain the cycle-level lane/timing/event comparisons.

The bounded generated case uses seed `20260920`, 32 fresh loaded programs, delays 1 through
31 selected by the seed, and a 256-edge limit. It predicts two retirements and the P3.2
schedule's `delay + 1` mechanism-wait stall observations independently. Failures report
seed, scenario, delay, retirement count, and observed stalls.

The exact prepared P2.6b image is `7804 0000 a300 7804 0001 0000`. The cycle test observes
the initial low commit, arms the real edge wait, injects pin 3, observes the wait decision,
the later decoded write request, the registered pin-0 commit, and normal halt. The
time-resolved test uses a ten-tick clock and all ten integer phases:

| Path | Measured latency |
| --- | --- |
| External pin-3 rise to synchronized rise | 10--19 ticks |
| Synchronized rise to core decision | 20 ticks |
| Core decision to software bank request | 30 ticks |
| Bank request edge to registered commit | Same edge, after the clock boundary |
| External rise to committed pin-0 high | 60--69 ticks |

The prepared direct observed-engine/bank path is 30--39 ticks, so this program's fetched
core-decision path adds exactly 30 ticks. The measured boundary is `Pin_bank.pins_o` and
`pin_oe_o`; there is no additional wrapper register. The sweep assumes stimulus scheduled
before an equal-time rising edge and does not claim analog CDC, setup/hold, pad, or routed
timing.

[`p3_integration_tb.v`](../tinytapeout/test/p3_integration_tb.v) repeats the exact loaded
wait/event/write image against emitted Verilog and an independent latency-one RAM, then
reruns it and ABORTs the active wait. It checks normal committed output and prompt pin/claim
release. `@rtl` separately performs Verilator lint and generic Yosys synthesis.
