# P3.5 independent hardware loader

Status: repaired and verified in emitted RTL at the reusable-core, behavioral-wrapper,
and production synthesis-wrapper boundaries. An independent review reproduced dispatch
after the original four-bit request-byte counter wrapped; that invalidated the earlier
completion claim. The repaired receiver saturates at the derived eleven-byte maximum,
latches overrun, and arms request/response intervals explicitly. This is digital
simulation evidence, not board or physical-timing evidence.

## Boundary and non-claims

P3.5 supplies fixed hardware framing, command dispatch, the real program-access
handshake, Tiny Tapeout wrapper integration, and testbench serial peers. It does
not implement an OS serial/USB device, a production host transport backend, board
I/O timing, or the two-image portable-API demonstration owned by P3.6. The loader
is independent of firmware and never reads or writes program RAM except through
`Integrated_core`'s P3.1a-owned request interface.

## Physical link and pins

| Physical pin | Name | Direction | Idle | Meaning |
| --- | --- | --- | --- | --- |
| `ui_in[0]` | `LSEL_N` | host to device | 1 | Active-low frame/response selection |
| `ui_in[1]` | `LCLK` | host to device | 0 | Host serial clock |
| `ui_in[2]` | `LDI` | host to device | 0 | Request data, MSB first within each byte |
| `ui_in[7:3]` | reserved | host to device | 0 | Ignored in wire version 1 |
| `uo_out[0]` | `LDO` | device to host | 0 | Response data, MSB first within each byte |
| `uo_out[1]` | `LRDY` | device to host | 0 | A complete response is retained and readable |
| `uo_out[7:2]` | reserved | device to host | 0 | Driven low in wire version 1 |
| `uio[7:0]` | protocol pins | bidirectional | released | Exclusively the programmable protocol bank |

`clk`, active-low `rst_n`, and `ena` retain their Tiny Tapeout harness meanings and
are not transport pins. Reset or disable immediately gates wrapper outputs low and
releases every `uio` output enable. Synchronized reset clears the parser, partial
byte, pending command, and pending response. Disable cancels the same loader state;
the core additionally cancels an incomplete load while preserving a completed
image.

The link resembles SPI mode 0 only at the electrical sampling boundary; it is not
advertised as a general SPI target. The device samples `LDI` when a synchronized
`LCLK` rising event reaches the system domain and changes `LDO` after a synchronized
falling event. `LSEL_N`, `LCLK`, and `LDI` use matching two-stage synchronizers. No
external-clock logic or CDC queue exists. In the race-free test convention, a pin
transition nominally coincident with a system rising edge occurs 1 ps after that edge;
the host requirements below do not rely on exact coincidence.

## Digital timing envelope

All durations are measured at the wrapper pins in system-clock periods:

| Requirement | Minimum |
| --- | ---: |
| `LSEL_N` low before first `LCLK` rise | 4 |
| `LCLK` high | 4 |
| `LCLK` low | 4 |
| `LDI` setup before `LCLK` rise | 4 |
| `LDI` hold after `LCLK` rise | 4 |
| Last `LCLK` fall before `LSEL_N` high | 4 |
| Inter-frame `LSEL_N` high | 4 |

At the declared 48 MHz system clock, a continuous symmetric bit clock is therefore
at most 6 MHz. This is not the whole transaction bound: an `N`-byte selected request
occupies at least `64N + 4` system periods through its trailing deselection, the host
then waits both the four-period high interval and `LRDY`, and an `M`-byte committed
response similarly needs `64M + 4` periods. Core read and ABORT completion add
device-dependent readiness latency. Slower clocks and arbitrary selected pauses are
legal; there is no inactivity timeout.

Request edge order for every bit is:

```text
host:    set LDI ----(>=4 Tsys)---- LCLK rise ----(>=4 Tsys)---- LCLK fall
device:                       synchronized rising event samples synchronized LDI
```

The first bit uses `LSEL_N` assertion as its launch boundary. Later data may change
at the preceding falling edge. Thus a 4/4 clock gives exactly four periods of setup
and four of hold in the digital contract; it deliberately claims no skew budget.

Response edge order is:

```text
host:    LSEL_N low --(>=4 Tsys)-- rise/sample -- high -- fall -- low -- rise/sample
device:  load first bit              synchronized fall advances to the next bit
```

The host samples the first and every later `LDO` bit on an `LCLK` rising edge. The
first bit is available before the first legal rise; each subsequent bit is available
after the preceding synchronized fall. For the final bit, the host samples on the
rising edge and validates framing, length, and CRC while keeping `LCLK` high. It then
chooses exactly one outcome:

| Outcome | Host sequence | Device effect |
| --- | --- | --- |
| Replay | Raise `LSEL_N` while final `LCLK` remains high; keep it high for at least four system periods before returning `LCLK` low | Final fall is absent, so the response remains retained and the next selection restarts at byte zero |
| Commit | Supply the final `LCLK` falling edge, wait at least four system periods, then raise `LSEL_N` | The fully shifted response is consumed and `LRDY` clears |

Stopping before the final bit and deselecting also retains the response. Stopping
with selection asserted simply pauses it. The inter-frame high interval is at least
four system periods, and a new request may start only after a committed response has
cleared `LRDY`. These are digital simulation/setup assumptions. They do not quantify
metastability MTBF, pad delay, cable integrity, or board-level timing.

## Request framing

Each request is exactly one selected frame:

| Byte offset | Field | Rule |
| ---: | --- | --- |
| 0 | magic | `0xa5` |
| 1 | wire version | `0x10` for major 1, minor 0 |
| 2 | tag | Host-selected correlation byte |
| 3 | command | Command table below |
| 4 | payload length low | Unsigned little-endian byte length |
| 5 | payload length high | Must be zero in version 1 |
| 6.. | payload | Exactly the command's fixed length, at most four bytes |
| last | CRC | CRC-8/ATM over every preceding byte |

CRC-8/ATM uses polynomial `0x07`, initial value `0x00`, no reflection, and final
XOR `0x00`. Bytes are processed in wire order, most-significant bit first. Selection
deassertion is the sole frame boundary and resynchronization point. The maximum request
is derived as six header bytes plus four payload bytes plus one CRC byte: eleven bytes.
The completed-byte count saturates there and a twelfth byte latches overrun. Once latched,
no suffix in that selection can restore dispatch eligibility. Extra bytes, partial bytes,
incomplete header/payload/CRC, bad magic/version/length/CRC, and an unknown command cannot
dispatch a core request. If all four magic/version/tag/command bytes were received, an
error response echoes tag and command; otherwise both fields are zero. A nonzero
payload-length high byte with an otherwise short transfer is `Incomplete` (`0x15`), because
its declared CRC position was never reached. Lengths 5 through 8 that arrive as complete
frames and explicit receiver overrun are `Bad_length` (`0x12`).

Multibyte payload integers are little-endian. Addresses and lengths are word units
and remain 16-bit until checked; values above 256 are never narrowed into the
eight-bit RAM address. A program word is `low-byte, high-byte`. `WRITE_WORD` and
`VERIFY_WORD` require both bytes in the same valid four-byte payload. There is no
padding, truncation, byte write, or incomplete trailing-word issue.

## Response framing and flow control

Responses use:

| Byte offset | Field | Rule |
| ---: | --- | --- |
| 0 | magic | `0x5a` |
| 1 | wire version | `0x10` |
| 2 | tag | Echoed request tag |
| 3 | command | Echoed request command |
| 4 | result | Result table below |
| 5 | payload length low | Unsigned little-endian byte length |
| 6 | payload length high | Zero in version 1 |
| 7.. | payload | Command-specific data |
| last | CRC | Same CRC-8/ATM definition |

Only one request or retained response exists. A command is received first,
validated after deselection, offered once to the core, and only then produces a
response. Receipt is therefore not acceptance. `Complete` means the core operation
and any required read/cleanup completion occurred. `Accepted_pending` is used only
for STOP because reaching its instruction boundary can be unbounded. A core refusal
is never reported as success.

While `LRDY=1`, a selection following at least four observed deselected system periods
starts a response read and request input is ignored.
Clocking may pause indefinitely. An interrupted or validation-rejected response remains
pending and restarts at byte zero on the next selection. A response read is armed only by
a selection edge observed while `LRDY` was already high. A selection made during dispatch,
READ completion, or ABORT cleanup cannot shift or consume the later response. Such an early
selection is unsupported traffic and is ignored until the host deselects and begins a new
legal selection. Retained request tag/command state cannot be overwritten by it.

Replay is not command retry. Within one enabled, unreset session, replay reads the same
retained response and does not offer the command again. Reissuing a committed command is a
new operation even if its tag is reused. Tags are correlation bytes, may be reused only
after commit, and do not provide duplicate suppression. Reset or disable discards retained
state, so an outcome lost across either boundary is uncertain; STATUS may diagnose some
states, but a side-effecting command such as RUN is not generally safe to reissue. No
general exactly-once guarantee is claimed.

## Commands

| Code | Command | Request payload | Successful response | P3.6 mapping |
| ---: | --- | --- | --- | --- |
| `0x00` | `INFO` | none | 13-byte version/capability/memory descriptor | discovery |
| `0x01` | `STATUS` | none | 12-byte state/progress/fault descriptor | status, loaded image, recovery diagnosis |
| `0x10` | `LOAD_START` | length u16 | none | first `load_image` operation |
| `0x11` | `WRITE_WORD` | address u16, word u16 | none | ordered complete-word writes |
| `0x12` | `READ_WORD` | address u16 | word u16 | bounded program readback |
| `0x13` | `VERIFY_WORD` | address u16, expected u16 | actual word u16 | hardware readback verification |
| `0x14` | `LOAD_COMPLETE` | none | none | image-valid authorization |
| `0x20` | `RUN` | none | none | RUN acceptance |
| `0x21` | `STOP` | none | none, `Accepted_pending` | STOP offer, then status polling |
| `0x22` | `ABORT` | none | none after cleanup | independent recovery control |

These numeric command values are the authoritative wire encoding. Fixed command payloads
are:

| Command | Request payload byte offsets | Response payload byte offsets |
| --- | --- | --- |
| `INFO`, `STATUS`, `LOAD_COMPLETE`, `RUN`, `STOP`, `ABORT` | none, length 0 | described below, or none |
| `LOAD_START` | `0..1`: image length u16 LE, length 2 | none |
| `WRITE_WORD` | `0..1`: address u16 LE; `2..3`: word u16 LE, length 4 | none |
| `READ_WORD` | `0..1`: address u16 LE, length 2 | `0..1`: actual word u16 LE, length 2 |
| `VERIFY_WORD` | `0..1`: address u16 LE; `2..3`: expected word u16 LE, length 4 | `0..1`: actual word u16 LE, length 2, including mismatch responses |

`INFO` has this authoritative 13-byte payload:

| Offset | Width | Encoding |
| ---: | ---: | --- |
| 0 | 1 | wire major, `1` |
| 1 | 1 | wire minor, `0` |
| 2 | 1 | ISA version, `1` |
| 3 | 1 | memory-layout ID, `1` for `m16` |
| 4 | 2 | capability mask u16 LE, currently `0x007f` |
| 6 | 2 | memory word bits u16 LE, `16` |
| 8 | 2 | memory depth u16 LE, `256` |
| 10 | 2 | maximum request payload bytes u16 LE, `4` |
| 12 | 1 | protocol-pin count, `8` |

Capability bit positions are stable wire values defined by `Wire.Capability` in
[`host_link_wire/wire.ml`](../host_link_wire/wire.ml), not by `Host_api.Capability`
constructor order:

| Bit | Mask | Meaning |
| ---: | ---: | --- |
| 0 | `0x0001` | `STATUS` |
| 1 | `0x0002` | `LOAD_START`, `WRITE_WORD`, `LOAD_COMPLETE` |
| 2 | `0x0004` | `READ_WORD` |
| 3 | `0x0008` | `VERIFY_WORD` |
| 4 | `0x0010` | `RUN` |
| 5 | `0x0020` | `STOP` |
| 6 | `0x0040` | `ABORT` |
| 7..15 | - | reserved, zero |

Simulator cycle control, external-pad injection, software trace storage, register
mutation, step, direct pin configuration, host queues, and trace retrieval are not
advertised.

`STATUS` has this authoritative 12-byte payload. Every multibyte value is little-endian:

| Offset | Width | Encoding |
| ---: | ---: | --- |
| 0 | 2 | flags u16 |
| 2 | 2 | image length in words u16 |
| 4 | 2 | words written u16 |
| 6 | 2 | words verified u16 |
| 8 | 2 | PC/instruction slot u16 |
| 10 | 1 | fault kind |
| 11 | 1 | execution phase |

| Flag bit | Mask | Meaning |
| ---: | ---: | --- |
| 0 | `0x0001` | enabled |
| 1 | `0x0002` | halted |
| 2 | `0x0004` | engines idle |
| 3 | `0x0008` | image valid |
| 4 | `0x0010` | load active |
| 5 | `0x0020` | verification failed |
| 6 | `0x0040` | execution active |
| 7 | `0x0080` | normal halt |
| 8 | `0x0100` | execution fault |
| 9 | `0x0200` | fetch fault |
| 10 | `0x0400` | at least one protocol-pin output enabled |
| 11 | `0x0800` | at least one software or engine pin claim |
| 12..15 | - | reserved, zero |

Fault-kind values are `0` none, `1` invalid base instruction, `2` invalid extension,
`3` fetch bounds, `4` truncated extension, `5` unrepresentable target, `6` mechanism
refused, `7` mechanism completion fault, `8` unsolicited completion, and `9` mechanism
protocol fault. Phase values are `0` halted, `1` fetch, `2` base wait, `3` extension
wait, `4` mechanism offer, `5` mechanism wait, and `6` fault; `7` is reserved. These
stable values are `Wire.Fault_kind` and `Wire.Phase`. They currently equal
`Control_execution.Fault` and `Control_execution.Phase`, so STATUS wires those fields
directly, and `Hardware_loader` refuses to elaborate if any value diverges.

STOP always reports `Accepted_pending` when its offer is accepted, including when the core
was already halted. The result means the STOP offer was accepted; STATUS determines whether
a boundary wait remains.

## Results and recovery

| Code | Meaning |
| ---: | --- |
| `0x00` | `Complete` |
| `0x01` | `Accepted_pending` |
| `0x10` | bad magic |
| `0x11` | incompatible wire version |
| `0x12` | bad, inconsistent, or oversized length |
| `0x13` | CRC mismatch |
| `0x14` | unsupported command |
| `0x15` | interrupted/incomplete frame |
| `0x20` | refused because execution is active |
| `0x21` | refused because an engine is active |
| `0x22` | refused because no verified image exists |
| `0x23` | address/image/sequence refusal |
| `0x24` | verification mismatch |
| `0x2f` | other hardware refusal/invariant failure |

`0x2f` is reserved for a refusal that cannot be classified by the stable results above;
the current composed core's accepted/rejected pairs are complementary during a valid
offer, so normal traffic does not emit it. Rejection is `request_valid & ~accepted`;
when no request is offered, both decisions are low. Richer refusal mapping remains a
P3.6 host-backend decision.

An accepted `LOAD_START` immediately invalidates the old image. Frame validation
happens before that offer, so a malformed start preserves the old image. Later
valid writes may have partial physical effects before an interrupted session, but
`image_valid` remains false. Transport CRC detects wire corruption; it does not
substitute for the second ordered `VERIFY_WORD` pass through actual RAM. Only an
accepted `LOAD_COMPLETE` after every successful comparison establishes validity.

Frame cancellation is selection loss before an exact frame. Load-session
interruption leaves the image invalid and is recovered by a new valid `LOAD_START`.
STOP requests a normal instruction boundary and cannot recover an indefinitely
blocked operation. ABORT is the fixed recovery command: it has priority over
STOP/step/RUN, cancels active core/mechanism work, releases claims and output
enables, and responds only after cleanup is observable. Device reset is separate,
invalidates every image, and does not initialize RAM.

## Resource bounds

The receiver stores six header bytes, at most four payload bytes, one partial byte,
CRC state, and parser counters. The transmitter uses one retained 21-byte response register
and a separate 21-byte shifting register (`INFO` is the largest). There is one command in
dispatch and at most one core read or ABORT completion wait. There is no request queue,
response queue, image buffer, inactivity counter, or automatic retry.

## Verification and P3.6 handoff

P3.5 testbenches encode and drive these physical pins, decode `LDO`, independently
check CRC/framing/results, and observe effects through wrapper outputs and later
commands. P3.6 should implement this byte/bit transaction engine beneath
`Host_api.Device`, preserve the existing structured refusal and timeout meanings,
and poll `LRDY` and `STATUS` with caller-provided finite budgets. Ordinary `load_image`
must preserve P3.4's refusal semantics and use `LOAD_START`, ordered `WRITE_WORD`, ordered
`VERIFY_WORD`, and `LOAD_COMPLETE`; an explicit recovery workflow may precede that with
ABORT. It must validate a complete response before commit, replay a retained response after
failed validation, and never turn uncertain post-reset completion into an automatic command
retry.

The following are P3.6 extensions, not P3.5 completion defects and not implemented here:

- add queue transport for portable data exchange;
- define unsupported behavior for hardware step, pin configuration, and trace operations;
- reconcile compact wire STATUS with the full portable inspection record;
- give infallible-looking `discover`, `loaded_image`, and `status` API operations an explicit
  transport-failure strategy;
- map simulator cycle budgets/advancement to physical elapsed time and finite polling;
- decide whether wire refusals need richer `Host_api.Error` mappings.

P3.6 must not advertise unsupported facilities or confuse a host timeout with a
device-generated result. Reset/disable outcome uncertainty may require an API change rather
than an invented `accepted` Boolean.

## Implementation

[`host_link_wire/wire.ml`](../host_link_wire/wire.ml) (library
`hardcaml_protemu.host_link_wire`, no Hardcaml dependency) is the one OCaml definition of
this record's wire values, layouts, and CRC parameters, and provides a software CRC,
request encoder, and response decoder for host code. It transcribes this record;
this record remains authoritative. The codec's decoder policy is recorded in
[the HL2 implementation record](host_link_hl2_record.md#decoder-policy-decisions).

[`hardware_loader.ml`](../lib/host_link/hardware_loader.ml) takes its wire constants from
`Wire` and contains the synchronizers,
CRC parser, four-byte request storage, sticky overrun/saturating count, armed request and
response intervals, one-shot dispatcher, core-completion waits, retained response store,
and separate response shifter. [`loader_core.ml`](../lib/host_link/loader_core.ml)
connects it to the actual `Integrated_core` program/control ports while retaining
an external latency-one RAM boundary. No loader state writes RAM, image-valid
state, execution state, registers, or mechanisms directly.

[`asic_bundle.ml`](../bin/asic_bundle.ml) adds the production `loader` project.
It connects `ui[2:0]` and `uo[1:0]` exactly as specified, passes all eight `uio`
pads only to the protocol bank, masks outputs during reset/disable, and supplies
the context-registered `program` resource with the established 256x16,
latency-one, explicit-Flops implementation selection. The manifest source set
names the loader, wire definitions, integrated core, mechanisms, ISA, and project
declarations.
`check-adopted-bundle.py --kind loader --metadata-only` checks repeatable metadata, pinout,
resource roles, and source copies only. Without `--metadata-only`, the checker additionally
runs behavioral wrapper simulation plus production synthesis-RTL lint and generic synthesis;
neither mode is physical evidence.

The physical peer is [`p3_loader_tb.v`](../tinytapeout/test/p3_loader_tb.v). It
constructs frames and CRC independently, drives only serial pins, decodes only
`LDO`, and observes results through responses, RAM requests at the reusable-core
tier, and public wrapper pins. It never loads internal memory hierarchically.
The same peer runs against emitted `loader_core` plus an independent latency-one 1RW store,
the actual adopted wrapper's behavioral source role, and the actual production synthesis
source role with its selected explicit-flop `program` RAM.

The peer must remain independent of the OCaml `Wire` library in `host_link_wire/`: do not
generate its constants, frame construction, CRC, or expected responses from that library
or RTL helpers. Shared-code OCaml codec tests (HL2, `test/host_link_wire/`) and the planned
Cyclesim harness (HL4) supplement this independent oracle.
[The host-link migration](host_link_migration.md) introduces those facilities while
preserving this record's protocol and all three peer tiers. Its backend handoff covers
existing commands; P3.6 queue transport still requires additional RTL support.

The directed sequence decodes INFO and STATUS payloads before and after valid/malformed
load starts, partial loading, overlength writes, verification failure, load completion,
execution, instruction fault, ABORT, and replacement execution. It exercises the reported
`16*0x00 + LOAD_START` and `16*0x00 + WRITE_WORD` attacks, 15-, 16-, 32-, and 48-byte
prefixes, an eleven-byte maximum legal frame, a twelfth byte, valid-looking suffixes, and
extra bytes after a valid frame. Rejection is checked through status/readback at every tier
and direct RAM write count at the reusable-core tier.

The peer also covers indefinite request pause, interrupted response replay, explicit final
bit reject/replay/commit, early selection during dispatch/READ/ABORT completion, reset and
disable cancellation, and correlation preservation. A side-effecting RUN starts a long
transfer that drives pin 1; deliberate peer-side response CRC rejection and replay leave its
output-enable assertion count at one. ABORT releases it with no stale reassertion. Separate
cases recover an infinite loop, a blocked RX queue pop, an active transfer, and an invalid
instruction fault, then serially load, verify, read, and run a Halt replacement.

The bounded malformed set uses LFSR seed `20260921` and sixteen deterministic trials across
CRC, truncation, extra-byte, and high-length-byte mutations, in addition to the directed
framing and command-size cases. Every mismatch reports the first correlation field or
expected/actual status, result, length, CRC, word, write count, or output event.

The guaranteed digital host envelope remains four system clocks for high, low, select
lead/trail, and data setup/hold. At 48 MHz this derives a 6 MHz symmetric bit clock, subject
to the complete frame/readiness overhead above. Race-free all-phase 4/4 and asymmetric 4/5
and 5/4 cases pass. A race-free 3/3 sensitivity sweep also passes all ten phases, replacing
the old single-phase statement, but remains unsupported because it violates the specified
four-cycle setup/hold/select envelope and leaves no reserved skew margin. A 1/1 all-phase
probe has excluded phases. These are digital sensitivity experiments, not physical signoff
or metastability evidence. No test establishes routed pad timing or board signal integrity.
