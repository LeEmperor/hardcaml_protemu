# P3.5 independent hardware loader

Status: implemented and verified in emitted RTL at the reusable core boundary and
the adopted Tiny Tapeout wrapper boundary. This is digital simulation evidence,
not board or physical-timing evidence.

## Boundary and non-claims

P3.5 supplies fixed hardware framing, command dispatch, the real program-access
handshake, Tiny Tapeout wrapper integration, and testbench serial peers. It does
not implement an OS serial/USB device, a production host transport backend, board
I/O timing, or the two-image portable-API demonstration owned by P3.6. The loader
is independent of firmware and never reads or writes program RAM except through
`Integrated_core`'s P3.1a-owned request interface.

## Physical link and pins

| Physical pin | Name | Direction | Idle | Meaning |
| --- | --- | --- | --- | --- |
| `ui_in[0]` | `LSEL_N` | host to device | 1 | Active-low frame/response selection |
| `ui_in[1]` | `LCLK` | host to device | 0 | Host serial clock |
| `ui_in[2]` | `LDI` | host to device | 0 | Request data, MSB first within each byte |
| `ui_in[7:3]` | reserved | host to device | 0 | Ignored in wire version 1 |
| `uo_out[0]` | `LDO` | device to host | 0 | Response data, MSB first within each byte |
| `uo_out[1]` | `LRDY` | device to host | 0 | A complete response is retained and readable |
| `uo_out[7:2]` | reserved | device to host | 0 | Driven low in wire version 1 |
| `uio[7:0]` | protocol pins | bidirectional | released | Exclusively the programmable protocol bank |

`clk`, active-low `rst_n`, and `ena` retain their Tiny Tapeout harness meanings and
are not transport pins. Reset or disable immediately gates wrapper outputs low and
releases every `uio` output enable. Synchronized reset clears the parser, partial
byte, pending command, and pending response. Disable cancels the same loader state;
the core additionally cancels an incomplete load while preserving a completed
image.

The link resembles SPI mode 0 only at the electrical sampling boundary; it is not
advertised as a general SPI target. The device samples `LDI` on synchronized
`LCLK` rising edges and changes `LDO` after synchronized falling edges. `LSEL_N`
and `LCLK` use two-stage synchronizers. `LDI` is sampled through the same two-stage
front end, and the timing contract below keeps it stable around the captured edge.
No external-clock logic or CDC queue exists.

## Digital timing envelope

All durations are measured at the wrapper pins in system-clock periods:

| Requirement | Minimum |
| --- | ---: |
| `LSEL_N` low before first `LCLK` rise | 4 |
| `LCLK` high | 4 |
| `LCLK` low | 4 |
| `LDI` setup before `LCLK` rise | 4 |
| `LDI` hold after `LCLK` rise | 4 |
| Last `LCLK` fall before `LSEL_N` high | 4 |
| Inter-frame `LSEL_N` high | 4 |

At the declared 48 MHz system clock, the symmetric boundary is 6 MHz. Slower
clocks and arbitrary pauses are legal; there is no inactivity timeout. The host
must stop issuing request clocks after deselection and must not select a response
until `LRDY=1`. `LRDY` remains high until a complete response has been clocked and
deselected. On response selection, the first `LDO` bit is available before the
first legal rising edge under the four-cycle select-lead rule. Subsequent bits
change after falling edges and are sampled by the host on rising edges. These are
digital simulation/setup assumptions. They do not quantify metastability MTBF,
pad delay, cable integrity, or board-level timing.

## Request framing

Each request is exactly one selected frame:

| Byte offset | Field | Rule |
| ---: | --- | --- |
| 0 | magic | `0xa5` |
| 1 | wire version | `0x10` for major 1, minor 0 |
| 2 | tag | Host-selected correlation byte |
| 3 | command | Command table below |
| 4 | payload length low | Unsigned little-endian byte length |
| 5 | payload length high | Must be zero in version 1 |
| 6.. | payload | Exactly the command's fixed length, at most four bytes |
| last | CRC | CRC-8/ATM over every preceding byte |

CRC-8/ATM uses polynomial `0x07`, initial value `0x00`, no reflection, and final
XOR `0x00`. Bytes are processed in wire order, most-significant bit first. Selection
deassertion is the sole frame boundary and resynchronization point. Extra bytes,
partial bytes, incomplete header/payload/CRC, bad magic/version/length/CRC, and an
unknown command cannot dispatch a core request. If a tag and command were received,
the error response echoes them; otherwise their response fields are zero.

Multibyte payload integers are little-endian. Addresses and lengths are word units
and remain 16-bit until checked; values above 256 are never narrowed into the
eight-bit RAM address. A program word is `low-byte, high-byte`. `WRITE_WORD` and
`VERIFY_WORD` require both bytes in the same valid four-byte payload. There is no
padding, truncation, byte write, or incomplete trailing-word issue.

## Response framing and flow control

Responses use:

| Byte offset | Field | Rule |
| ---: | --- | --- |
| 0 | magic | `0x5a` |
| 1 | wire version | `0x10` |
| 2 | tag | Echoed request tag |
| 3 | command | Echoed request command |
| 4 | result | Result table below |
| 5 | payload length low | Unsigned little-endian byte length |
| 6 | payload length high | Zero in version 1 |
| 7.. | payload | Command-specific data |
| last | CRC | Same CRC-8/ATM definition |

Only one request or retained response exists. A command is received first,
validated after deselection, offered once to the core, and only then produces a
response. Receipt is therefore not acceptance. `Complete` means the core operation
and any required read/cleanup completion occurred. `Accepted_pending` is used only
for STOP because reaching its instruction boundary can be unbounded. A core refusal
is never reported as success.

While `LRDY=1`, selection starts a response read and request input is ignored.
Clocking may pause indefinitely. If selection rises before all response bits are
read, the response remains pending and restarts at byte zero on the next selection.
After all bits, selection must rise before `LRDY` clears. No buffer can be
overwritten and no destructive command is repeated by response retry.

A host that loses a response must inspect `STATUS` before retrying a side effect.
Tags correlate a response but do not provide replay suppression. In particular,
retrying `LOAD_START` intentionally restarts the session, retrying an accepted
sequential write is refused because progress advanced, and retrying RUN can observe
active execution. This makes uncertain outcomes diagnosable without an unbounded
transaction cache.

## Commands

| Code | Command | Request payload | Successful response | P3.6 mapping |
| ---: | --- | --- | --- | --- |
| `0x00` | `INFO` | none | 13-byte version/capability/memory descriptor | discovery |
| `0x01` | `STATUS` | none | 12-byte state/progress/fault descriptor | status, loaded image, recovery diagnosis |
| `0x10` | `LOAD_START` | length u16 | none | first `load_image` operation |
| `0x11` | `WRITE_WORD` | address u16, word u16 | none | ordered complete-word writes |
| `0x12` | `READ_WORD` | address u16 | word u16 | bounded program readback |
| `0x13` | `VERIFY_WORD` | address u16, expected u16 | actual word u16 | hardware readback verification |
| `0x14` | `LOAD_COMPLETE` | none | none | image-valid authorization |
| `0x20` | `RUN` | none | none | RUN acceptance |
| `0x21` | `STOP` | none | none, `Accepted_pending` | STOP offer, then status polling |
| `0x22` | `ABORT` | none | none after cleanup | independent recovery control |

`INFO` returns a 13-byte payload containing wire major, wire minor, ISA version,
memory-layout ID (`1` for
`m16`), capability bits u16, memory-word bits u16, memory depth u16, maximum
request payload u16, and protocol-pin count. Capabilities advertise only hardware
discovery/status, program load/read/verify, RUN/STOP/ABORT, and the protocol pin
count. Simulator cycle control, external-pad injection, software trace storage,
register mutation, direct pin writes, and host queue operations are not advertised.

`STATUS` returns flags u16, image length u16, words written u16, words verified
u16, PC u16, fault kind u8, and execution phase u8. Flags expose enabled, halted,
engines-idle, image-valid, load-active, verification-failed, execution-active,
normal-halt, execution-fault, fetch-fault, protocol-pin output active, and protocol
pin claimed. This is enough to distinguish an interrupted load, live execution,
background ownership, fault/halt state, and ABORT completion.

## Results and recovery

| Code | Meaning |
| ---: | --- |
| `0x00` | `Complete` |
| `0x01` | `Accepted_pending` |
| `0x10` | bad magic |
| `0x11` | incompatible wire version |
| `0x12` | bad, inconsistent, or oversized length |
| `0x13` | CRC mismatch |
| `0x14` | unsupported command |
| `0x15` | interrupted/incomplete frame |
| `0x20` | refused because execution is active |
| `0x21` | refused because an engine is active |
| `0x22` | refused because no verified image exists |
| `0x23` | address/image/sequence refusal |
| `0x24` | verification mismatch |
| `0x2f` | other hardware refusal/invariant failure |

An accepted `LOAD_START` immediately invalidates the old image. Frame validation
happens before that offer, so a malformed start preserves the old image. Later
valid writes may have partial physical effects before an interrupted session, but
`image_valid` remains false. Transport CRC detects wire corruption; it does not
substitute for the second ordered `VERIFY_WORD` pass through actual RAM. Only an
accepted `LOAD_COMPLETE` after every successful comparison establishes validity.

Frame cancellation is selection loss before an exact frame. Load-session
interruption leaves the image invalid and is recovered by a new valid `LOAD_START`.
STOP requests a normal instruction boundary and cannot recover an indefinitely
blocked operation. ABORT is the fixed recovery command: it has priority over
STOP/step/RUN, cancels active core/mechanism work, releases claims and output
enables, and responds only after cleanup is observable. Device reset is separate,
invalidates every image, and does not initialize RAM.

## Resource bounds

The receiver stores six header bytes, at most four payload bytes, one partial byte,
CRC state, and parser counters. The transmitter retains at most one 21-byte
response (`INFO` is the largest). There is one command in dispatch and at most
one core read or ABORT completion wait. There is no request queue, response queue,
image buffer, inactivity counter, or automatic retry.

## Verification and P3.6 handoff

P3.5 testbenches encode and drive these physical pins, decode `LDO`, independently
check CRC/framing/results, and observe effects through wrapper outputs and later
commands. P3.6 should implement this byte/bit transaction engine beneath
`Host_api.Device`, preserve the existing structured refusal and timeout meanings,
poll `LRDY` and `STATUS` with caller-provided finite budgets, and perform load as:
`ABORT`, `LOAD_START`, ordered `WRITE_WORD`, ordered `VERIFY_WORD`,
`LOAD_COMPLETE`, optional `READ_WORD`, then `RUN`. It must not advertise unsupported
capabilities listed above or confuse a host timeout with a device-generated result.

## Implementation

[`hardware_loader.ml`](../lib/hardware_loader.ml) contains the synchronizers,
CRC parser, four-byte request storage, one-shot dispatcher, core-completion waits,
and retained 21-byte response shifter. [`loader_core.ml`](../lib/loader_core.ml)
connects it to the actual `Integrated_core` program/control ports while retaining
an external latency-one RAM boundary. No loader state writes RAM, image-valid
state, execution state, registers, or mechanisms directly.

[`asic_bundle.ml`](../bin/asic_bundle.ml) adds the production `loader` project.
It connects `ui[2:0]` and `uo[1:0]` exactly as specified, passes all eight `uio`
pads only to the protocol bank, masks outputs during reset/disable, and supplies
the context-registered `program` resource with the established 256x16,
latency-one, explicit-Flops implementation selection. The manifest source set
names the loader, integrated core, mechanisms, ISA, and project declarations.
`check-adopted-bundle.py --kind loader` checks repeatable metadata, pinout,
resource roles, source copies, and production RTL lint/synthesis paths.

The physical peer is [`p3_loader_tb.v`](../tinytapeout/test/p3_loader_tb.v). It
constructs frames and CRC independently, drives only serial pins, decodes only
`LDO`, and observes results through responses, RAM requests at the reusable-core
tier, and public wrapper pins. It never loads internal memory hierarchically.
The same peer runs against emitted `loader_core` plus an independent latency-one
1RW store and against the actual adopted wrapper's simulation source role,
including its behavioral context-registered `program` resource.

The directed sequence covers INFO and STATUS; all ten integer phases; minimum
4/4-cycle halves; 4/5 and 5/4 asymmetric halves; an observed 3/3-cycle point just
outside the guaranteed envelope; indefinite mid-request clock pause; response
interruption/restart; bad magic, version, command, CRC, payload length, oversize,
wide address, incomplete frame, and incomplete trailing word; no malformed-write
side effect at the exposed RAM tier; hardware verification mismatch and premature
completion; RUN without an image; active-execution read refusal; ABORT of a
one-word infinite jump; pin release; replacement with a Halt image; readback and
RUN; and reset/disable cancellation. The fixed generated set uses LFSR seed
`20260921`, 16 CRC-corruption trials, and the testbench's finite response budget.
Every mismatch reports the correlation field or expected/actual result, length,
CRC, or word.

The guaranteed digital host envelope remains four system clocks for high, low,
select lead/trail, and data setup/hold. At 48 MHz this is 6 MHz with symmetric
halves. All ten integer phases passed at that boundary. Both asymmetric boundary
cases passed. The tested 3/3-cycle point also passed in two-state RTL, but remains
outside the guarantee because it does not supply the reserved CDC and physical
margin needed to broaden the contract. No test establishes metastability
reliability, routed pad timing, or board signal integrity.
