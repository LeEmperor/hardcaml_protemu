Conclusion: the legacy path completes and the design closes with margin on all
three reported corners, with every required physical check at zero. As a
baseline it is sound. As a path to keep, it is not: producing this record
required finding and working around three separate defects, none of which the
adopted path has.

## Defects found while producing this record

1. **The timing gate reported a false failure.** `harden-cmos5l.sh` collected
   every metric whose name contains "drc" and "error", which swept up
   `route__drc_errors__iter:0..3` — the detailed router's convergence history,
   not its result. A run that converged 17 → 4 → 2 → 0 was reported as "the
   design does not close" and exited 8. Fixed by excluding `__iter:` keys; the
   fixed gate was re-applied to this run's preserved `metrics.csv` and returns
   pass, and still fails correctly on injected negative slack, nonzero
   `route__drc_errors`, and nonzero `magic__drc_error__count`.

   The run in this record was executed under the unfixed gate. Its
   `harden-summary.json` is left as written, because regenerating it now would
   stamp a later, dirty working tree onto a run made from a clean one.
   `metrics.csv` is the immutable source of truth either way.

   The same bug fails the adopted run's metrics too (13 → 13 → 6 → 0), so this
   was a defect in the gate, never a difference between the two designs.

2. **The gate-level target omits a required PDK file.** `tinytapeout/test/Makefile`
   passes `sg13cmos5l_io.v` and `sg13cmos5l_stdcell.v` but not
   `sg13cmos5l_udp.v`. The standard-cell models instantiate `ihp_dff_r`, which
   is defined in the UDP file, so elaboration failed with `ihp_dff_r referenced
   13 times` — once per flop. This target cannot ever have passed on a design
   with sequential logic on this PDK.

3. **The gate-level target assumes a host `iverilog`.** There is none on this
   machine; the 2026-09-14 record lists Icarus 12.0 as a local tool, so it was
   lost in a machine move. The adopted path never had this dependency: it runs
   Icarus from the pinned LibreLane image.

The gate-level result above was produced by supplying the missing UDP file and
running Icarus 13.0 from the pinned LibreLane image, which is also what the
adopted path uses:

```sh
docker run --rm --pull=never --user 1000:1000 \
  -v "$PWD:$PWD" -v "$PDK_ROOT:$PDK_ROOT:ro" -w "$PWD/tinytapeout/test" \
  --entrypoint env ghcr.io/librelane/librelane:3.1.0.dev3 \
  sh -c 'iverilog -g2012 -Wall -Wno-timescale -DGL_TEST -DFUNCTIONAL -DSIM -s tb \
    -o ../build/rtl-test/p0_wrapper_gate \
    $PDK_ROOT/ihp-sg13cmos5l/libs.ref/sg13cmos5l_io/verilog/sg13cmos5l_io.v \
    $PDK_ROOT/ihp-sg13cmos5l/libs.ref/sg13cmos5l_stdcell/verilog/sg13cmos5l_udp.v \
    $PDK_ROOT/ihp-sg13cmos5l/libs.ref/sg13cmos5l_stdcell/verilog/sg13cmos5l_stdcell.v \
    <netlist> tb.v && vvp ../build/rtl-test/p0_wrapper_gate'
```

Only defect 1 has been fixed in the repository. The `Makefile` is unchanged:
whether to repair a target on a path being retired, or to delete it, is a
decision this record does not make.

Limitations: timing here is analysed without an SDC, so these slack numbers
describe LibreLane's default constraints rather than this design's declared
ones, and are not directly comparable to the adopted run's. See the P0.5b
record for that comparison. No board evidence. The run archives only to the
ignored `tinytapeout/build/` tree; the legacy path has no equivalent of the
adopted flow's `archive` stage.
