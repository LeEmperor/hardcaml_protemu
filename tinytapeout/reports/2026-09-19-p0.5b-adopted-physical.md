## Differences from P0.5a

Every verdict agrees: both designs close, and DRC, LVS, antenna, precheck and
the gate-level test are identical results on both paths. The gate-level
simulation prints the same message and finishes at the same time on both
netlists. The measured differences are these.

| | legacy (P0.5a) | adopted (P0.5b) |
| --- | --- | --- |
| synthesis sources | 2 files | 1 generated module |
| SDC | none supplied | generated, used for PnR and signoff |
| mapped standard cells | 129 | 154 |
| instance count | 71,079 | 71,085 |
| routed wirelength | 2,738 µm | 3,435 µm |
| worst setup slack | +11.3135 ns | +15.5891 ns |
| worst hold slack | +0.15566 ns | +0.14745 ns |

The single cause behind all of it is the constraint set. The legacy
configuration supplies no SDC and none of the six timing constraints listed
above, so its numbers describe LibreLane's defaults; the adopted run is
analysed against constraints derived from the declaration, including a real
driving cell, an output load and declared I/O delays. The two slack figures
therefore measure different questions, and the adopted run reporting more
slack on every corner is **not** evidence that the adopted design is faster.
What it does establish is that the adopted design closes under stated,
reviewable constraints rather than under defaults nobody chose.

The cell and wirelength deltas follow from the same place: a constrained flow
sizes and buffers differently, and the adopted path compiles one generated
module where the legacy path compiles a generated core plus a hand-written
wrapper. The 6-instance and 697 µm differences are consistent with that and
with nothing else observed; no attempt was made to attribute them
path-by-path, which would need the placement and STA reports rather than the
final metrics.

## Identity and the later declaration

The physical run above predates the `Tt_cmos5l` template adoption
(`hardcaml_asic` `a257424c3ae31fd6ee10cea052cc7577f15d2677`), which moved the
twenty LibreLane overrides and the fixed TT interface into the library and cut
`bin/asic_bundle.ml` from 208 lines to 153. Re-emitting from the current
declaration at `7e29ecd16b3bd57dd4e14955132d1c28c565c833` produces identity
`b699c8160775d269dd9fec5e6c17541cbc426c4bb9b5bf23952ed17b9626690b` — but every
emitted file is byte-identical: `src/config.json`, `constraints/top.sdc`,
`info.yaml`, and both the synthesis and simulation RTL (SHA-256
`c275808a7279c617…` for each). `generated_settings`, `flow_configuration`,
`target` and `resources` are unchanged.

The identity moved because `bin/asic_bundle.ml` and
`tinytapeout/asic-dependencies.lock` are themselves declared inputs, and
because `resolved_settings` now carries per-setting `reason` text in place of
the copied template string. No override *value* changed. The physical result
in this record therefore still describes what the current declaration emits,
and the tree is now clean, so a re-emission is reproducible from its recorded
revision in a way the original was not.

Conclusion: the adopted path reproduces the legacy path's physical result from
a declaration rather than from hand-maintained configuration, with its
constraints stated instead of defaulted, and it does so as one command. The
legacy path required three defect workarounds to produce its own baseline
(recorded in the P0.5a record); the adopted path required none.

Limitations: no board evidence. LibreLane's own `KLayout.DRC` and XOR steps are
off by declared default, so `klayout__drc_error__count` is absent from the final
metrics and KLayout coverage comes from TT precheck after the flow rather than
from the flow itself; the override's reason records the measured cost of
turning it on (478.64 s). The declared I/O delays remain provisional P0 harness
assumptions, not board-derived. Utilization is 0.247%, so nothing here
exercises placement or routing under pressure; P0.7 memory is the first work
that will.
