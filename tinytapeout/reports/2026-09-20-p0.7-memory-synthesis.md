## Implemented

`bin/asic_bundle.ml` retains the existing observable declaration and adds a
selectable `memory` declaration. It connects P3.1a's plain-Hardcaml
`Protocol_core` port to one context-registered `Single_port_ram` named `program`.
The project policy is explicitly `Flops`; simulation elaboration uses the
library behavioral model and implementation elaboration uses generated flop
RTL with a registered read output and no initialization.

The consumer shape is the adopted P3.1a/P1.5 default: 256 sixteen-bit words
(4,096 storage bits), one whole-word 1RW port, and one-cycle reads. The TT
fixture stages complete 16-bit words over two cycles, exposes all eight address
bits, and maps a zero load-start length to 256 so synthesis cannot discard an
unreachable portion of the declared resource. It is a diagnostic adapter, not
the P3 loader or host protocol.

Validity, sequential load coverage, ordered full-word verification, image bounds,
halted/engine-idle access gating, response ownership, and reset/disable behavior
remain in `Protocol_core`. Reset invalidates consumer metadata and never clears
RAM. Rejected accesses issue no RAM operation, and post-write, unwritten, stale,
or held outputs are consumed only when independently tracked response validity
is asserted.
